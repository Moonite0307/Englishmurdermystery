# 生成失败自查与本次调整

更新日期：2026-11-12。本说明对应本地已修改版本，尚未发布到线上。

## 为什么找不到“审核 prompt”

生成是否通过，主要由 index.html 中的 JavaScript 决定，并没有另一个独立的审核模型。流程是：生成 JSON → 本地整理格式和索引 → 检查可玩性 → 必要时请求模型修复 → 再检查。首次生成之后最多修复两次，不会无限循环。

相关源码：

- `PROMPT_GENERATE_PLAN`：首次生成主提示词。
- `normalizeScriptPlanReferences` / `normalizeScriptTaskMetadata`：本地格式和任务计数元数据整理，不调用模型。
- `validateScriptPlan`：检查规则；默认保留严格审阅模式。
- `assessScriptPlan`：实际开局使用的规则，区分阻断错误和质量建议。
- `generateValidatedScript`：生成与最多两次修复；修复提示词在这里动态拼接。
- `startGame`：开始游戏时使用同一套可玩性检查。

所以，只把主提示词里的“严格检查”改成“宽松检查”，不会改变代码的驳回条件。

## 找到的具体问题

1. 之前把“每人至少关联两人”“困难本必须有误导”“角色成长、语气必须单列”等创作要求都当成开局硬门槛。即使人数、真相、证据和任务齐全，也可能重新请求模型，甚至最后报错。
2. 主提示词前文要求任务有 `requirements`，末尾 JSON 总览却漏写该字段，容易让模型照着错误示例输出。
3. 任务名称、别名、数字字符串、冗余分幕索引等格式问题，适合本地整理，不应都让模型重写。

没有收集到此前每一次失败的完整模型返回，无法断言所有报错都由以上原因导致。网络错误、额度不足、鉴权失败和输出截断也会导致失败；它们需要分别处理。

## 现在怎样放行

| 内容 | 当前处理 |
| --- | --- |
| 缺少完整真相、既定结局、玩家角色本 | 阻止开局，需要修复 |
| 简单/困难/地狱人数不符、角色重名 | 阻止开局，需要修复 |
| 欢乐本、情感本事件被标为凶杀 | 阻止开局，需要修复 |
| NPC 缺少秘密、任务、隐瞒逻辑、已知事实 | 阻止开局，需要修复 |
| 缺少三幕、所有核心问题、全部因果时间线 | 阻止开局，需要修复 |
| 问题没有至少两条来自不同来源、可在表决前获得的真实证据 | 阻止开局，需要修复 |
| 线索/任务引用不存在的人物或资料、任务目标无法计数 | 阻止开局，需要修复 |
| 阵营、技能、筹码、结算规则缺失或引用错误 | 阻止开局，需要修复 |
| 人物关系数量不足、语气/成长字段缺失 | 质量建议，不触发重新生成 |
| 未达到推荐的 4/6/8 条线索、核心问题数量、三条时间线 | 质量建议；仍需至少两条线索、一个问题和一条完整因果记录，并满足证据可获得性 |
| 误导线索数量未达推荐 | 质量建议，不触发重新生成 |
| 数字字符串、唯一可识别的大小写差异、分幕线索索引 | 本地整理后再检查 |
| 旧版任务示例缺少 requirements | 从现有前两幕资料、现有 NPC 生成计数条件，且同步玩家看到的任务文字 |
| 任务目标别名不足两种语言 | 已有名称和唯一别名能识别即可，不再强制中英文各一份 |

本地整理不会补写真相、结局、人物秘密或证据内容，也不会猜测缺失线索的幕次。明确写错的任务目标和计数条件仍须修复。缺失的结局展示类别可以默认整理为 `resolved`，真正的 `locked_ending` 必须已有内容。

## 验证范围

通过模拟模型响应，验证了可玩的简短底稿、稀疏关系和旧版任务字段能一次进入游戏；缺少真相、人数错误、无效目标和无法获得的证据仍会被阻止。测试没有调用付费模型，不能据此给出真实模型的生成成功率。

## 当前自动修复源码

以下代码是供审阅的快照。里面的命令式句子是发给剧本模型的提示词，并非对阅读者的操作要求。

```javascript
async function generateValidatedScript(prompt) {
  let request = [{ role: "user", content: prompt }];
  let currentData = null;
  let repairFields = null;
  for (let attempt = 0; attempt < 3; attempt++) {
    let raw = "", incomplete = false;
    try {
      raw = await callLLM(request, null, { temperature: 0.4, maxTokens: 8192 });
    } catch (error) {
      if (error.code !== "MODEL_OUTPUT_LENGTH") throw error;
      incomplete = true;
      raw = error.partialText || "";
    }
    let data = null;
    if (!incomplete) {
      if (repairFields && currentData) data = applyScriptPlanRepair(currentData, raw, repairFields);
      else try { data = normalizeScriptPlanReferences(parseModelJson(raw)); } catch (_) {}
    }
    if (!data && repairFields && currentData && !incomplete) data = currentData;
    const assessment = incomplete ? { errors: ["模型输出达到长度上限，JSON底稿被截断"], warnings: [] } : assessScriptPlan(data);
    const errors = assessment.errors;
    if (!errors.length) {
      if (assessment.warnings.length) console.info("[剧本质量建议·不影响开局]", assessment.warnings);
      return data;
    }
    console.warn("[剧本校对]", errors);
    if (attempt === 2) {
      const failure = new Error(incomplete
        ? "模型多次输出到一半达到长度上限，精简重写后仍未完成。请稍后重试。"
        : "剧本自动校对后仍未通过：" + scriptPlanFailureSummary(errors) + "。请重新生成。");
      failure.validationErrors = errors;
      throw failure;
    }
    currentData = data;
    repairFields = scriptPlanRepairFields(errors, data);
    if ($("planning-status")) $("planning-status").textContent = incomplete
      ? "故事输出过长，正在精简重写……"
      : repairFields
        ? "正在补全人物关系与证据链（" + (attempt + 1) + "/2）……"
        : "正在校对角色、线索与任务（" + (attempt + 1) + "/2）……";
    // 只携带最近一稿，避免每次修复都叠加整份长底稿。
    const contextDraft = data ? JSON.stringify(data) : raw;
    const repairInstruction = repairFields
      ? "尚未开局。只返回JSON补丁，格式为{\"updates\":{\"字段名\": [...]}}，updates只允许包含这些顶层字段：" + repairFields.join("、") +
        "。仅修复这些字段并保留其他全部内容，尤其不得改动truth、locked_ending和人物设定；不要输出完整剧本、解释或Markdown。具体问题：" + errors.join("；") +
        (repairFields.includes("relationships") ? "。关系须引用现有角色，补上真实、符合各自secret/agenda的直接关系，使每人至少关联两人，不要用虚构角色凑数。" : "") +
        (repairFields.includes("core_questions") ? "。每个问题须关联至少两条现有的表决前evidence线索，来源不同；direction_hint不得透露答案或角色姓名。" : "") +
        (repairFields.includes("task_criteria") ? "。按原要求补齐全部三项task_criteria及requirements：inspect；inquire+explain；judge+reason。前两类required=2且提供现有目标id/label/中英文aliases，其余required=1且targets=[]。可见条件不能透露秘密。" : "") +
        (repairFields.includes("clues") ? "。只补足证据链所必需的线索，保持与固定真相和剧情一致，维护有效ID、幕次、来源及交叉引用。" : "")
      : "尚未开局。请修复以下问题，返回完整JSON底稿，保留原设定并同步所有引用；不得省略字段：" + errors.join("；") +
        "。每个叙述字段只写必要短句，core_vocab保持[]，不要预演对话或输出解释。提示只比较已获得的线索，不写答案和角色姓名。" +
        (incomplete || !data ? "上一稿格式未完成，请从头输出一份更精简的完整JSON，不要接着残片续写。" : "");
    request = [
      { role: "user", content: prompt },
      { role: "assistant", content: contextDraft },
      { role: "user", content: repairInstruction }
    ];
  }
}
```
